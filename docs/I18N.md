# Internationalization Contract

## Supported locales

- `zh-CN`：历史数据与未标语言持久化内容的兼容语言。
- `en`：完整英文界面及系统生成邮件。
- 匿名首次访问、没有有效语言 Cookie 的界面默认使用 `en`；这不会改写历史业务内容的语言归属。
- `when2entretien_locale` Cookie 是界面语言的请求级来源，路径必须与 `NEXT_PUBLIC_BASE_PATH` 一致。

## Rendering and data boundary

所有产品文案都使用 `MessageKey`。Server Components 通过 `getServerTranslator()` 在 SSR 阶段翻译；Client Components 通过 `useLocale().t()` 翻译。同一个消息键使用同一份 catalog，因此 hydration 前后文本一致。

禁止：

- 遍历或监听 `document.body`；
- 按中文源句匹配任意 DOM 文本；
- 翻译候选人姓名、邮箱、备注、面试组名称/说明、会议地址、管理员备注或邮件自定义正文；
- 使用本地化展示文案作为业务状态或比较值。

Server Action 与 Zod 返回的历史中文系统消息由 `translateKnownSource()` 在消费边界处理。该函数只接受中文 catalog 中精确登记的整句，或含显式 `{valueN}` 占位符的已登记模板；占位值只有在自身也是精确登记的系统文案时才翻译。未知字符串逐字返回，因此数据库内容、姓名、备注和服务商错误不会进入通用翻译器。新代码优先直接返回稳定 `MessageKey`/错误码。

语言切换先写入 basePath 范围的 Cookie，再刷新 Server Component payload。React 合并 RSC payload 时保留已挂载 Client Component 的表单状态。候选人页面同时把语言同步到当前组的 `CandidateSession.locale` 与 `Candidate.preferredLocale`。

## Authentication locale

新候选人访问链接携带一次性的 `?lang=` 提示；确认页读取后立即从地址栏移除。隐藏表单使用已经解析的 locale，不依赖异步 React state 更新。没有 `lang` 的旧链接不强制中文，而是由 token 保存的 locale 或现有界面 Cookie 决定。

## Email locale policy

- 候选人访问链接、候选人通知和候选人的预约/改约/取消邮件：使用候选人的 `preferredLocale`。
- 批量候选人通知同时提交经人工确认的中英文主题与正文；同一批次逐位按 `preferredLocale` 选择内容，并以该语言及时区格式化日期。界面预览必须分别检查两种内容语言。
- 全局邮件模板以 `(key, locale)` 独立保存。模板管理页的内容语言是显式选择器，不跟随界面语言切换；重置一种语言不得影响另一种语言。
- 面试官预约邮件：使用执行排期操作的后台界面 locale；当前数据模型没有面试官个人语言偏好。
- 后台操作产生的组 OWNER 通知：使用触发操作的后台界面 locale，而不是候选人的语言。
- 候选人提交产生的 OWNER 通知：使用 `STAFF_NOTIFICATION_LOCALE`（默认 `zh-CN`），因为此时没有后台操作者。
- outbox 行保存已经渲染的 subject/body/ICS 和 locale；重试不得按当前 UI 语言重新渲染。

## Database migration

`0015_i18n_locale_persistence` 为 `Candidate`、`CandidateAccessToken`、`CandidateSession` 和 `CandidateEmailDelivery` 增加非空 locale 字段及允许值约束；同时将 `EmailTemplate` 从仅 `key` 唯一改为 `(key, locale)` 复合唯一。历史行和已有模板覆盖均回填为 `zh-CN`，不会复制成未经审核的英文内容。

新版本应用读取这些字段，因此部署顺序必须是：

1. 备份并验证数据库备份；
2. 执行 `pnpm exec prisma migrate deploy`；
3. 确认 `0015_i18n_locale_persistence` 已应用；
4. 再切换并启动新应用版本。

## Required verification

```bash
pnpm i18n:check
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
NEXT_PUBLIC_BASE_PATH=/when2entretien pnpm build
```

Playwright 的 `tests/e2e/i18n.spec.ts` 验证：无 Cookie 首次访问默认英文、一次点击立即更新 Server Components、切到中文时未提交表单值不丢、刷新后语言保留、basePath Cookie 生效，以及禁用 JavaScript 时英文已经存在于 SSR HTML。

`pnpm i18n:check` 同时扫描 `.ts` 与 `.tsx` 中的中文系统源文案，拒绝未入 catalog 的 action/validation 消息，并拒绝已知的 raw action-state 渲染路径。TypeScript AST 门禁还会拒绝 JSX 中 `t(...)` 与原始数据直接拼句、多个独立 `t(...)` 拼句，以及把一个 `t(...)` 的结果嵌入另一个消息占位符。发布流程只允许 `generate-catalogs.mjs --check`；生成脚本不会改写正式 catalog。需要补充词条时，显式运行 `--generate-review-candidate` 只会生成隔离的候选文件，人工校对后再合入正式 catalog。
